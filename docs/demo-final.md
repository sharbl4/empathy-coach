# Empather · shertwg^3 · маршрут защиты

Empather — практика развития эмпатии для людей, которым трудно понимать чувства других. Возможные трактовки помогают уточнять, а не читать мысли. Мы не обещаем доказанного роста эмпатии и не ставим диагнозов.

## Перед показом

Использовать только отдельный @test_empather_bot и вымышленные сообщения. Домашний GPU-ПК должен быть включён: QQCloud сам не выполняет inference. Проверить health, домашнюю Gemma и сохранённый результат в истории. Никаких секретов, email, ссылок входа или кодов на демонстрационном экране/в логах. Войти и подтвердить почту заранее; доставка письма не укладывается в 90 секунд и зависит от SMTP.

Текущий deploy SHA, итоговый PR и свежие проверки находятся в [integration-progress](integration-progress.md); исторические зелёные тесты не заменяют live-приёмку.

## Основной маршрут на 60–90 секунд

| Время | Действие | Ожидаемый результат |
|---|---|---|
| 0–10 с | Коротко назвать цель; открыть «Попробовать на примере» / «Примеры» | 8 вымышленных ситуаций, разные отношения/контексты; никаких готовых анализов |
| 10–25 с | Выбрать «Давай завтра» для коллеги; своя версия «усталость», точная цитата «завтра» либо «Не понимаю» | Пользователь сначала формулирует гипотезу; модель ещё не вызывается |
| 25–35 с | Открыть полный очищенный preview, проверить поля/контекст/гипотезу и подтвердить | Подтверждается именно показанный snapshot; редактирование требует нового показа |
| 35–60 с | Дождаться настоящей Gemma | Несколько трактовок, неизвестное, основания и нейтральный уточняющий вопрос; скорость заранее не гарантируется |
| 60–80 с | «Написать ответ»: «Я не могу сегодня. Давай завтра». Подтвердить новый preview | Отзыв на свой черновик и «До и после» из уже полученного результата; отказ/границы нужно проверить самому |
| 80–90 с | Открыть историю, затем готовый результат повторно | Сохранённый анализ; чтение не вызывает повторную генерацию |

Две генерации могут не уложиться в 90 секунд: для короткого выступления показать одну новую, а сравнение черновика — заранее сохранённое и честно обозначенное как предыдущий реальный результат. Не выдавать сохранённый результат за мгновенно сгенерированный. Не запускать новую генерацию автоматически после ошибки.

Для второй трактовки той же фразы выбрать близкого человека в каталоге: меняется контекст, а не заготовленный ответ. Это отдельный реальный запрос после нового preview.

## Дополнительные сценарии, если есть время

- Из разбора: упражнение → своя попытка → preview → отзыв; роль «обиженный» → три своих ответа с preview каждого → итог; завершение раньше доступно после первого ответа.
- «Продолжить»: оставить черновик/карточку/тест, открыть меню или веб-историю, восстановить из серверного dialogue. Дождаться надписи о сохранении; idle TTL 1 час, общий максимум 24 часа. Сброс требует отдельного подтверждения.
- Карточки/практика дня/навыки/прогресс/своя оценка; opt-in уведомления оставить выключенными для защиты, не рассылать другим людям.
- Тест до/после: показать сохранение частичных ответов и рубрику 0–2. Повтор через 7 дней; нельзя ускорять production-часы или обещать доказанный психологический эффект.
- HTTPS после публикации: получить одноразовую ссылку в Telegram → явно подтвердить вход в веб → та же история → logout. Ссылку не показывать в записи выступления.

## Резервный маршрут

Если модель недоступна, показать понятную ошибку, доступные историю/карточки/настройки и уже сохранённый результат с обозначением происхождения. Не выключать рабочий домашний ПК для сценки. Изолированный offline-тест не является доказательством поведения реального выключенного ПК.

Если HTTPS недоступен, показывать настоящий тестовый Telegram-бот; веб обозначить как локально проверенный через реальные HTTP/DB и явные test adapters. Не называть localhost публичной публикацией. Владелец повторяет `/publish 8000` в @gg_domains_bot после восстановления сервиса организаторов; приложение слушает 0.0.0.0:8000, домен atlas.gg.qqtech.ru. Агент не отправляет эту команду.

## Проверено / не проверено

| Проверено | Границы доказательства / не проверено |
|---|---|
| Живой test bot → QQCloud → Gemma; три сохранённых успешных результата, доставка и повторное открытие пользователем после рестарта подтверждены на f57f6d0 после восстановления служебной очереди | Новый разбор/история подтверждены владельцем, не все режимы и не web HTTPS |
| Отдельная настоящая PostgreSQL, ownership, revision/snapshot, идемпотентность, позднее удаление, auth/CSRF/lifecycle; точные результаты финального набора в журнале | Explicit test model/mail/Telegram adapters не являются live-службами |
| Browser linked login/history/logout и новые сценарии проверяются Playwright на настоящем HTTP/DB | HTTPS-вход с чужого телефона и общая история на площадке ещё блокируются публикацией |
| Cloud test backup восстановлен в отдельную БД, записи сравнены приватно | Восстановление реальной production DB, VM/ПК reboot и длительный сетевой offline не проверены |
| Невалидный ответ отклоняется, генерация не подменяется fixtures | Полный quality review Gemma, VRAM, cold/warm p50/p95/TTFT, суммарная нагрузка не аттестованы |

Все 27 функций раздела 7 остаются в текущем объёме. Список API/кнопок не равен полной пользовательской приёмке; открытые ограничения перечислены в журнале, а не скрыты в roadmap.

Операционный риск: при зависшем inbox возможна ограниченная остановка poller. Проверять health перед выступлением; не крутить старые кнопки и не запускать второй poller. Последнее разрешённое владельцем recovery и сохранность данных описаны в integration-progress; автоматического повтора генерации нет.
