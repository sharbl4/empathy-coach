# apps/bot — Telegram-интерфейс «Между строк»

Зона Дани. Единственный пользовательский интерфейс: grammY 1.46.0, long polling, один процесс. HTTP backend и Supabase не используются.

## Запуск

```sh
npm run build -w @between/contracts && npm run build -w @between/bot
TELEGRAM_BOT_TOKEN=... node apps/bot/dist/main.js   # сейчас останавливается: фасада домена ещё не подключена
npm test -w @between/bot                            # сценарии через mock Telegram transport
```

Env бота: `TELEGRAM_BOT_TOKEN` (обязателен; пустой или неверный формат — ошибка конфигурации), `BOT_DELIVERY_INTERVAL_MS` (200–60000, по умолчанию 1500), `NODE_ENV`. DATABASE_URL, LOCAL_LLM_*, SMTP_* читает фасада домена, не бот.

## Точка интеграции (нужно от Антона и Димы)

`src/domain.ts` — порт `BotDomain`: всё, что боту нужно от домена. Это **предложение** сигнатур фасады; его надо проверить и закрепить в contracts. `src/facade.ts` — единственное место подключения; сейчас бросает ошибку и не подставляет фикстуры.

Ключевые решения порта:
- `UserContext {telegramId}` создаёт только transport из `ctx.from.id`. ID из callback — только ссылки, владельца проверяет домен (чужое → `NOT_FOUND`).
- Inbox: `acceptUpdate(update_id)` → false для повторной доставки; `completeUpdate` в finally.
- FSM: `state` / `setState(name, payload, expectedVersion)` с `STATE_CONFLICT`. Версия шага зашита в callback_data, поэтому старая кнопка → «Этот шаг уже завершён».
- Предпросмотр: `preview(fields)` → маскированная копия + `id/revision` + `safety`. Любой AI-вызов с текстом пользователя принимает `previewId+revision`, модель до подтверждения не вызывается.
- Idempotency: ключ = sha256(telegramId, версия шага / preview revision, действие) в UUID-форме. Двойной клик и повтор update дают тот же ключ.
- Runs возвращаются сразу (`queuePosition`). Результат приходит через outbox `claimDeliveries` → `markDelivered` / `markUndeliverable`. Delivery ничего не генерирует.
- `retry(runId)` предложен для **всех** failed run (домен повторяет сохранённый подтверждённый snapshot; сейчас в contracts retry есть только для roleplay).
- Предложенные расширения DTO (необязательные поля): `interpretations[].evidenceLevel` (text/context/insufficient), `analysis.comparison`, `phraseFeedback[].tone/why/softer`, DTO «Сказать прямо» (`DirectOutput`), `difficulty`, `contextType`, `rateRun`, `track(StageEvent)`.

## Реализовано в боте

/start, /menu, /cancel, /history, /account, /help; только private chat (в группах — короткая подсказка на команды, без сохранения); онбординг → почта → код (неверный код, истечение, блокировка, повтор, смена адреса); «Понять сообщение» по шагам с «Назад» / «Пропустить» / /cancel; «Сначала твоя версия» с проверкой цитат; предпросмотр всех полей с «Отправить в модель / Редактировать / Отмена»; разбор с категориями оснований и сравнением; «Как уточнить?» из сохранённого разбора; «Полезно / Не полезно»; черновик → тепловая карта (🟠/🟡/🟢 со словами, «Почему?», «Вариант мягче») → примеры под 4 цели; «Нужен пример»; упражнение → попытка → отзыв; роль с тремя уровнями, счётчиком 1/3 и ранним завершением; «Сказать прямо» со своей попыткой и повтором с другой целью; каталог вымышленных примеров; сценарий опасной ситуации без номеров; история по 5 с фильтром сфер, просмотр, продолжение, удаление с подтверждением; прогресс; удаление учебных данных и отдельно аккаунта с честным описанием объёма; plain text без parse_mode, нарезка < 3500 символов, 429 retry_after (≤ 2 повторов, ≤ 30 с), 403 → прекращение доставки.
