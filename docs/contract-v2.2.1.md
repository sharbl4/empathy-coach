# A1 2.2.1 · approved integration decisions

Совместимое расширение2.2, без новой фасады/обязательных параметров всех методов. FEATURE-27/список bindings не является E2E evidence.

1. DialogueNavigation.assessment допустима при step=assessment И step=menu. Меню сохраняет ту же canonical форму/version/answers. Никакой второй копии partial answers. Domain запрещает update/reset, уничтожающие существующий unfinished assessment, без явного подтверждения: resetDialogue input расширен OPTIONAL confirmation:'DISCARD_UNFINISHED_ASSESSMENT' + прежний expectedRevision. Обычные reset без assessment остаются совместимы. Другая новая форма не должна подменять старый draft. После successful submit очистка атомарна и не требует второго discard. TTL/отзыв/удаление по прежней политике2.2 остаются отдельными причинами очистки; меню не продлевает/не отменяет эту политику. UI предлагает Continue / Explicit reset; остальные незавершённые сценарии не уничтожаются молча.
2. RunV2 дополнен OPTIONAL myRating:null|'useful'|'not_useful'. Это wire-совместимость со старыми DTO, не разрешение серверу скрывать vote. Обновлённый backend всегда загружает поле для owned run/detail/runs/session history из product_votes по user+run; null означает нет голоса, undefined — старый/неполный ответ. Существующие run(ctx,{id}), sessions detail/runs и HTTP GET уже несут общий DTO; новых сигнатур/endpoint не нужно. rateRun upsert возвращает прежний Vote; frontend восстанавливает состояние после reload, не начинает всегда с null.
3. StageEvent (клиентский recordStage) больше не принимает run_completed. Полный DomainStageEventName сохраняет его для OperationalAnalytics. Единственный writer — доменный successful run transaction, UNIQUE(user,name,resource), repeat completion/intent не создаёт второй event. Failed/invalid/late/deleted runs не записывают success event. Клиентская попытка → VALIDATION_ERROR, даже для своего run.
4. ThreadTurn {id,speaker,text} + ordered SessionInputV2.turns и updateSession/ComposerDraft уже поддерживают edit/reorder. Новая DTO/операция не нужны. Telegram обязан показать выбор существующей реплики, правку по стабильному turnId и перемещение вверх/вниз; не имитировать это delete+recreate с новым ID. Изменение persisted input повышает revision и инвалидирует preview; draft navigation сохраняется с revision.
