## Что установлено по коду

Веб-клиент обращается непосредственно в Supabase Auth; пароль передаётся Auth-провайдеру, backend проверяет Bearer через getUser. Supabase SDK сохраняет Auth-сессию в браузере (persistSession=true). Backend хранит учебные данные в PostgreSQL и передаёт контекст заданий в GigaChat; автоматической гарантированной очистки персональных данных в тексте нет. Fastify logger отключён.

Удаление отдельной ситуации и DELETE /api/me/data реализованы. Второе удаляет учебные ситуации и связанные записи, но сохраняет Auth-аккаунт и профиль. Автоматического удаления Auth-аккаунта, журнала согласий и отдельного Telegram-канала в проверенной версии нет. Переписка, результаты и входы/выходы модели не должны попадать в журналы.

Это проверка исходного кода на базе main 7e893b361a93d4a57cfd20edf4b723b76f1f1245, а не аудит размещения, договоров, кабинетов и резервных копий.

## Публикация и передача команде

После закрытия таблицы оператор утверждает редакцию и дату действия. Опубликовать полный текст политики на HTTPS без входа; разместить ссылки при регистрации, перед вводом и в профиле. Для бота указать свой Privacy Policy в @BotFather, предоставить /privacy и /delete_data с фактическими обработчиками, отдельную кнопку согласия и отказа. Имена команд здесь — согласуемое требование, не существующие функции.

Политику и согласие публиковать раздельно. При изменении цели/состава обработки сначала проверить правовое основание; изменения не считать принятыми задним числом. Историю редакций хранить без пользовательских текстов.

Дима: оценить серверное хранение согласий/отзывов, жизненный цикл аккаунта, удаление/backup и безопасную проверку Telegram-событий. Даня: отдельный экран согласия, ссылки и напоминание об удалении идентификаторов; никаких обещаний об анонимности/мгновенном удалении везде. Новые API/контракты — только отдельным согласованным изменением. Стек, приложения, DTO, зависимости и lockfile этим PR не меняются.
